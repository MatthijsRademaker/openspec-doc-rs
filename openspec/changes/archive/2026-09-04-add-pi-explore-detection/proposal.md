## Why

A pi.dev exploration is invisible to the reviewer. `.pi/extensions/openspec-doc-hook.ts` calls `hook prompt` at `before_agent_start` and `hook stop` at `agent_end`, so pi gets the directive loop and the self-starting dashboard for free — but nothing on pi's side ever calls `hook explore`. No scratch note is created, so the session page has nothing to render, no text can be selected, and no comment can be anchored. The session is never registered under the review-material predicate either, so it does not even appear in the index. For the phase this tool exists to support, pi is not wired up.

Everything below the extension is already agent-agnostic. `openspec-doc hook explore --agent pi` is an accepted invocation today, reads `sessionId` from the same stdin payload the extension already sends for `prompt` and `stop`, and returns the same resolved note path and dashboard URL. The missing piece is one handler in one TypeScript file.

The gap has been documented rather than fixed, and the documentation has grown into a design. `AGENTS.md` carries three paragraphs weighing `pi.on("input")` against `before_agent_start`, ruling out `pi.registerCommand`, and citing pi 0.84.3's type declarations — reasoning that belongs in a change, not in the file the agent reads as standing instruction. `init` prints a warning about the gap on every pi configuration, and `project-init`'s spec requires it to. All three describe a defect instead of naming a behaviour, and all three go stale the moment the handler exists.

## What Changes

- Call `hook explore --agent pi` from the pi extension when the submitted input is an explore invocation, so a pi exploration produces the same scratch note, the same emitted path, and the same review registration a Claude Code exploration does.
- Match on raw input before skill and template expansion, covering both ways an explore starts on pi: the `/opsx-explore` prompt template and the `/skill:openspec-explore` skill.
- Stop reporting the gap from `init`, and drop the spec requirement that it be reported. A warning about a capability the tool now has is worse than no warning.
- Delete the pi-gap analysis from `AGENTS.md`. The decisions it argues move into this change's design, where they can be reviewed and then archived.

Out of scope, and deliberately kept: the Claude Code gap where an exploration started through the `Skill` tool fires no `UserPromptExpansion` hook and creates no note. That paragraph of `AGENTS.md` stays as it is, with its instruction to write the note by hand. It is a different mechanism with a different fix, and the repository owner has accepted it for now.

## Capabilities

### New Capabilities

None. Explore detection already exists as a capability; this change makes it true on a second harness.

### Modified Capabilities

- `explore-note-capture`: explore detection is currently specified against one harness's command-expansion event. It becomes a requirement on every supported harness, including one that has no such event and must match raw input instead.
- `project-init`: pi extension installation no longer reports that pi explorations are uncaptured, and the scenario requiring that report is removed.

## Impact

- `crates/cli/assets/openspec-doc-hook.ts` — the one copy of the extension, embedded in the binary.
- `.pi/extensions/openspec-doc-hook.ts` — this project's copy, regenerated by `openspec-doc init --yes`.
- `crates/cli/src/init/mod.rs` — the pi warning, and the test asserting it.
- `AGENTS.md` — the unmanaged pi-gap section. The managed block does not mention the gap and is untouched.
- pi.dev's extension API, whose `input` event this change starts depending on.
